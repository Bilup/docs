Bilup 在編輯器中內建了完整的 Git 版本控制系統。它跟蹤專案的歷史，讓您可以提交快照、回顧更改、在分支上工作並推送到託管倉庫。整個倉庫（包括其歷史）**位於專案檔案內部**，因此它隨 `.sb3` 一起旅行。

版本控制適合較大或長期的專案，它是透過拉取請求而不是即時編輯進行協作的基礎。

## 開啟版本控制

開啟**工具**選單並選擇**Git**，這會開啟**版本控制**視窗。左側的側邊欄在更改、歷史、分支、差異、遠端、Bilup Accounts Git 和自述檔案之間切換。

如果專案尚未受版本控制，您會得到**初始化倉庫**選項來開始一個，或一個透過 URL **克隆**現有專案的欄位。

## 提交更改

**更改**檢視列出自上次提交以來每個更改過的檔案，每個都標有狀態：已修改、已新增或已刪除。編寫描述更改的訊息並點選**提交**。**撤銷上次提交**反轉最近的一次。點選更改的檔案會開啟它的差異。

您也可以讓 Bilup 在每次儲存時替您提交：在**版本控制**[設定](/editor/settings)頁面上開啟**儲存專案時自動提交**，您還可以在那裡設定提交作者名稱和電子郵件。

## 歷史與差異

**歷史**列出您的提交，每個都有訊息、短雜湊和顏色編碼的分支圖。選擇提交可以看到它更改的檔案、將專案恢復到它，或將其下載為 `.sb3`。

**差異**顯示您的工作更改與上次提交之間的可讀逐行比較。因為 Bilup 比較的是專案的文本表示而不是原始 JSON，新增和刪除是清晰的：您實際上可以讀到指令碼中發生了什麼變化。

## 分支與合併

**分支**讓您建立、切換和刪除分支，這樣您可以在不干擾主線的情況下開發功能。要合併分支，選擇一個源分支並**預覽**合併。

如果合併有衝突，Bilup 會列出每個衝突檔案，並要求您為每個選擇一方，**我們**或**他們**，然後**應用合併**。對於更復雜的情況，**在編輯器中解決**會用常見的衝突標記開啟程式碼編輯器中的衝突檔案，讓您手動解決。

## 遠端與託管

**遠端**管理通用的 Git 遠端倉庫（例如 GitHub 倉庫）：用 URL 和存取令牌新增遠端倉庫，然後向其推送分支。

**Bilup Accounts Git** 是內建的託管後端，執行在 git.accounts.bilup.org 上。當您用[Bilup Accounts 帳戶](/getting-started/introduction)登入時，您可以建立倉庫、直接從編輯器推送專案、克隆任何 Bilup Accounts 倉庫，而無需設定單獨的存取令牌。倉庫可以是公開的或私有的。沒有單獨配置憑證的步驟：使用您的 Bilup Accounts 登入。

**自述檔案**編輯專案的 README，它儲存在倉庫中並隨其他所有內容一起在 `.sb3` 內旅行。
